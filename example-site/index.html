Spore

A web that outlives its hosts

You are reading this from a torrent. No web server sent you this page. It came from someone's open browser tab, and while you read it, your browser is offering it to the next person.

The problem is hosting, not publishing

Publishing on the web is free. Staying published is not. Every page you can read exists because somebody is paying for a server, renewing a domain, and remaining reachable — and because nobody with leverage over that host has asked them to stop.

So the web has one failure mode, wearing several costumes:

  • Takedown. Pressure the host, the registrar, or the payment processor. The content does not need to be illegal, only inconvenient to someone with a lawyer.
  • Link rot. Nobody renews. Nobody is attacked. The page simply stops, because the person maintaining it lost interest, funding, or their life.
  • Consolidation. Hosting is cheapest at scale, so most of the web now sits on a handful of providers. A small number of decisions can unmake a large number of pages.

These look like different problems. They are one problem: a page has exactly one home, and that home has an owner who can be reached.

What Spore does

Spore addresses a site by the hash of its contents rather than by the name of a machine. Ask for a site and any peer holding those bytes can answer; the hash proves the answer is right. There is no host to petition, because there is no host — only whoever currently has a copy.

Concretely, it is one static page — the gate — that does two things:

  1. Opens a site from a magnet link. The site renders in your browser, fetched from other people's browsers over WebRTC.
  2. Publishes a folder. Drop a folder with an index.html; it is hashed in your browser and you get a link. It is never sent to a server, because there is no server — it goes to readers directly, and only to those who ask for it.

The gate itself is a handful of static files with no backend, so it can be re-hosted by anyone in a minute. Taking down one gate accomplishes nothing: the same link opens on any other. How it works, in detail →

Why adoption is not a vanity metric

For most projects, users are a measure of success. For Spore, users are the infrastructure — adoption is not evidence that it works, it is the mechanism by which it works.

A site lives as long as somebody has it open. One reader is a single point of failure wearing a different hat. A hundred readers is a hundred independent copies, in a hundred jurisdictions, with no shared owner and nobody to serve a notice on.

This inverts the usual economics of the web. Normally, popularity is a cost: more readers, more bandwidth, a larger bill, and a bigger target. Here, popularity is redundancy. The pages most worth removing are the ones hardest to remove, because being widely read is the same act as being widely hosted.

Which is also the honest catch. Spore is weakest at exactly the moment a publisher needs it most: the beginning, when one person has the only copy. It does not manufacture resilience. It converts attention into resilience, and it needs attention to convert.

Who this is for

Spore solves one problem — the host went away — and solves it well. It solves nothing else. That makes the audience specific:

  • Archivists and preservationists. Documentation, datasets, fan wikis, the corpus of a dead forum. The threat is not censorship, it is entropy: somebody stops paying and a decade evaporates. A magnet link shared among people who care is a backup that serves itself.
  • Writers and researchers who want a permanent link. A paper, a report, a personal site. Publish once, and the address stays valid without renting anything, forever, as long as one reader cares.
  • People publishing something inconvenient. Where the danger is the work being removed — read the limits below carefully, because if the danger is being identified, this is the wrong tool and will get you hurt.
  • Anyone who wants to run a mirror. Hosting a gate costs a static file host and nothing else. Every mirror makes every site reachable from one more address.

Equally, who it is not for: anything needing a database, logins, payments, or content that changes by the minute. Spore hosts documents, not applications.

What it refuses to promise

A tool that overstates itself gets people hurt, so plainly:

  • It is not anonymity. Peers in a swarm see each other's IP addresses — that is how the transfer happens. Spore protects content from removal. It does not hide who published or who is reading, and no amount of adoption changes that.
  • It is not always-on yet. A browser seeds only while its tab is open. Close every tab that has a site, and the site sleeps until someone with a copy opens it again. The bytes are not lost; nobody is holding them out.
  • Sites do not change yet. A magnet addresses fixed bytes, so an edit produces a new address. Mutable pointers are planned; they are not here.

Where this is going

Today: open a site, publish a site. That is the whole of it, and it works.

Next: mutable pointers, so a site can be updated without a new address, and a signed index so sites can be found rather than only shared. After that: seeders that run outside a browser, so a site survives everyone closing their tab — and a gate pinned by its own hash, so you can verify the gate before trusting it with a page.

The useful thing you can do right now is the boring one: publish something, and keep this tab open a little longer than you need to.
